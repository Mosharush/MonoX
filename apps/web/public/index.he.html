Monorepo generator ו-delivery contracts

מייצרים את המוצר ואת ה-delivery path ביחד.

פקודה אחת כותבת workspaces ל-web, API ו-worker, מגדירה dependency boundaries, מחברת local services, CI ו-containers, ונותנת מסלול ברור ל-PM2, Coolify או Kubernetes. המפתחים וה-coding agents עובדים מול אותו contract בכל package.

מציצים ל-0.2 alpha רואים את הקוד
יוצרים מוצר deterministic recipes

הפקודה תהיה זמינה אחרי שה-prerelease המוגן יתפרסם תחת next.

npm create monox@next -- my-product \
  --workspace api=node-fastify-api \
  --workspace web=react-vite-web \
  --workspace jobs=node-worker \
  --addon redis --addon rabbitmq \
  --delivery docker:local --yes

עד אז @latest נשאר ה-release היציב. בחירה שלא נתמכת נכשלת לפני ש-MonoX כותב קבצים או משנה infra.

מה הפקודה באמת כותבת

Repo עם מקום ברור לקוד של המוצר, לקוד reusable ול-infra

ה-recipes מגיעים bundled ו-versioned. הקובץ monox.lock שומר version ו-integrity, כדי שגם במחשב אחר יהיה ברור בדיוק מה יצר את המבנה.

ה-setup ש-MonoX מוריד מהדרך

מה כבר לא צריך לחבר ידנית

MonoX אורז את החלטות הפלטפורמה שחוזרות בכל פרויקט. החלטות המוצר עדיין נשארות אצלכם.

  1. 01

    Workspace setup

    Package manager, workspace globs, dependency direction ו-boundaries משותפים ל-agents.

  2. 02

    Local runtime

    Health routes, קבצי Docker ושירותים שבחרתם, עם placeholders שחייבים למלא בקובץ local ignored.

  3. 03

    Verification

    Immutable install, בדיקת lock, פקודות test ו-build בתוך ה-CI שנוצר.

  4. 04

    Delivery model

    Workloads typed, probes, limits, scaling signals ו-plan שמותאם ל-target.

מ-local עד production

ה-contract נשאר קבוע, ה-target מתחלף

ה-package מתאר את ה-workload. ה-target שבחרתם משלים image, namespace, domain, identity ו-secret bindings.

  1. Validateעוצר unknown fields, inline secrets ו-targets לא חד משמעיים.
  2. Explainמראה את ה-defaults, ה-profile, ה-environment וה-variant לפי הסדר.
  3. Planקושר source, config, target state ו-adapter digests.
  4. Applyרץ דרך ה-local executor המובנה או transport שמחובר במפורש, ודוחה plan לא עדכני. 
monox validate
monox config explain @my-product/jobs --env staging
monox plan --env staging --all --output .monox/plan.json
monox apply --plan .monox/plan.json

MonoX מגדיר את הגבול. אתם אחראים למה שעובר דרכו.

אתם מספקים cloud access דרך OIDC או workload identity, בוחרים domains ו-managed services, מגדירים budgets ו-capacity, מחברים external secrets ומאשרים שינויים ב-production.

MonoX לא מחליף cloud control plane, לא מבטיח capacity אצל ה-provider ולא מחביא פעולות destructive בתוך deploy רגיל.

הוכחות של 0.2 alpha

מה כבר ממומש, מה guarded ומה עדיין מחכה ל-production proof

הסטטוס מחובר לטסטים ב-repo הציבורי. Claims עתידיים נשארים בחוץ עד שיש להם הוכחה.
